# Node types

This is a map: the parts that turn a node type into components and systems, in C and in C#, and
what each hands on. How a part works inside is on the generated page of its file. The contract is
`src/c/framework/kernel_engine/framework/node_types.h`, the plugin `src/zig/framework/`, the C#
SDK `src/csharp/framework/KernelEngine.Framework.Nodes/` and its generator
`src/csharp/generators/KernelEngine.Framework.Nodes.Generator/`.

## The parts

| part | where | receives | hands on |
|---|---|---|---|
| `ke_node_types` | the framework plugin | a `ke_node_type_desc`: name, fields, initial bytes, `with`, behaviours, events | a tag per type, its fields registered as a component, one system per behaviour |
| `engine_node_types.h` | `src/c/framework/` | nothing | the engine's node types as data: each component's initial value, each type's `with` |
| `NodeTypes`, `NodeCtx` | generated by kabic | the vtables | `RegisterType`, `Spawn`; a behaviour's context with `Fields<T>`, `Get<T>`, `Raise<T>` |
| `EngineNodeTypes` | generated by kabic from `engine_node_types.h` | nothing | the initial values, the `with` arrays, `RegisterEngineNodeTypes` |
| bases (`Node2D`, `Body2D`, `Label`...) | generated by `NodeBasesExtension` from the `[node:]` tags | a component tagged with a node name and its base | an abstract class reaching the component and adding it to `With` |
| `Node`, `NodeWorld` | `Sdk/` | a node instance; the node types | the binding of one instance to the node a behaviour visits; ids by name and by type |
| `NodeTypeGenerator` | the generator project | a partial class marked `[NodeType]` deriving from `Node` | its fields struct, property bodies, field table and `RegisterInto` |

## What ties the parts together

**A behaviour is one call over the nodes of its type.** Each of `ready`, `update`, `fixed_update`
and `on` runs as a system of its phase; the body walks the nodes with `next`, which points
`self` and `fields` at each one in turn. An `on` behaviour walks every pair of a node and an event
of a type it lists, and `event_type` says which.

**A type's nodes are born with its initial bytes.** The fields and every `with` component start
from the bytes the type was registered with, unless a spawn gives the component.

**One C# instance stands for every node of its type.** `NodeWorld.Register` hands the instance to
`RegisterInto`, which the generator writes; a behaviour binds the instance to the node `next`
moves to, so a partial property reads and writes that node's fields. Outside a behaviour the
properties are the bytes a node is born with, which is why the value the constructor gives them
becomes the type's initial value.

**The generator writes calls, not memory.** What it emits uses only `RegisterType`, `INodeCtx` and
the SDK's `Node`; no pointer reaches the game's code.

## What the parts agree on without a contract

- The component name of a `[node:]` base: the struct name without "ke_" and "_component"; its
  initial value is `ke_<name>_node_initial` of `engine_node_types.h` when that defines one.
- A C# node type's field names: the snake case of its property names.
- An event type registered by `NodeWorld.RegisterEvent<T>` is named by the full name of `T`.
- Diagnostics: "KENG001" a node type that is not partial, "KENG002" an instance field that is not
  readonly, "KENG003" an exported property a field table cannot describe.
